# 垫片补偿可达性判定（Shim Reachability）

光学平台校准时，A、B 两级垫片只能提供离散的微米补偿值。本工具对工程师粘贴的
JSON 进行**精确求解**：对每个目标值 `t`，判断是否能从 A、B 两级中**各选一片**
使 `a + b = t`，并按目标原序逐项输出 `reachable` 布尔结论。

- React 18 + TypeScript 单页，Vite 构建，纯前端计算、无任何后端/假接口/固定响应。
- Vitest 以朴素枚举为参考，交叉验证朴素小样本、稠密集合与稀疏集合。
- 满规模（各 100,000 项）输入在常规笔记本上约 **0.2–0.5 秒**完成全部判定，
  远低于 6 秒预算（禁止枚举 A×B，最坏 10¹⁰ 次数对会冻结浏览器）。

## 输入格式与边界

根对象**有且仅有** `a`、`b`、`targets` 三个字段：

```json
{
  "a": [0, 100, 200000],
  "b": [0, 50, 200000],
  "targets": [0, 150, 400000, 150, 399999]
}
```

| 项目 | 类型 | 元素数量 | 元素取值 |
| --- | --- | --- | --- |
| `a` / `b`（垫片规格，微米） | 整数数组 | 1 – 100,000 | 0 – 200,000 |
| `targets`（目标值） | 整数数组 | 1 – 100,000 | 0 – 400,000 |

规则：

- **重复垫片值视为同一规格**（例如 `[100,100,100]` 等价于 `{100}`）。
- **目标保留顺序与重复项**；重复目标只计算一次，结论保证一致、可复算。
- 每项只输出 `reachable: boolean`。
- 以下任一情况统一显示 **`INVALID_INPUT`**，并立即移除旧答案：
  - 非法 JSON（含 `NaN`/`Infinity` 等 JSON 不支持的字面量）
  - 根不是对象，或字段多于/少于 `a`、`b`、`targets`（额外字段不允许）
  - 任一字段不是数组，或数组为空，或元素数超过 100,000
  - 任一元素不是整数（`1.5`、`true`、`null`、字符串等均拒绝）
  - 垫片值超出 `[0, 200000]`，或目标值超出 `[0, 400000]`

## 算法（精确且不枚举数对）

垫片值域有界 `[0, 200000]`。先以 `Int8Array` 成员表对 A、B 去重，再把两个集合
编码成单个 `BigInt` 位集：

- `bitA` 的第 `i` 位为 1 ⇔ `i ∈ A`
- `bitBR` 的第 `i` 位为 1 ⇔ `(200000 - i) ∈ B`（B 的反向位集）

目标 `t` 可达 ⇔ `bitA` 与“按 `t` 对齐后的 `bitBR`”存在公共置位：

```
t ≤ 200000 :  bitA & (bitBR >> (200000 - t))  ≠ 0
t > 200000 :  bitA & (bitBR << (t - 200000))  ≠ 0
```

BigInt 按 64 位分块做 AND，单目标约 `200001/64 ≈ 3126` 次机器字位运算；
100,000 个目标为亚秒级。另有和区间剪枝（稀疏集合直接跳过位运算）与目标缓存
（重复目标零成本）。

## 本地开发

```bash
npm install
npm run dev        # Vite 开发服务器
npm test           # Vitest 一次性运行全部测试
npm run verify     # 类型检查 + 测试 + 生产构建（验收命令）
npm run preview    # 本地预览构建产物
```

## Docker Compose

构建并运行静态站点（nginx 托管 `dist/`）：

```bash
docker compose up --build          # http://localhost:8080
WEB_PORT=9000 docker compose up --build
```

宿主机端口由环境变量 **`WEB_PORT`** 控制，默认 `8080`（容器内固定 80）。

一次性验收服务 `verify`：在干净的 node:20-alpine 环境中执行
`npm ci` + `npm run verify`（TypeScript 类型检查 → Vitest → Vite 构建），
输出结论后退出，退出码即验收结果：

```bash
docker compose --profile verify run --rm verify
```

> Web 镜像构建阶段本身也会执行 `npm run verify`，任何一步失败镜像都不会产出。

## 结果展示

结果严格按目标原序排列，逐行给出目标数值与 `true（可达）/ false（不可达）`，
汇总区显示目标数、可达/不可达计数、去重后规格数与耗时，便于工程师核对
**零值、最大边界（400000）与重复目标**的结论一致且可复算。
